1. ひとことで言うと
════════════════════════════════════════

ねるトレは、寝る前に書いた日記をAIが読み、「書いた言葉どうしのつながり」を見せるアプリです。

日記が続かない理由の一つは、続けても変化が見えないことです。
そこで、次のようなつながりを見つけて、本人に見せることにしました。

  ・3日前に書いた「分からない」への答えが、後の日の日記に書かれていた
  ・「〇〇だけは」と思っていたけれど、実際に気分が良かったのは別のことをした日だった
  ・週の前半と後半で、使っている言葉が変わっていた

このつながりを、AIに正確に見つけてもらうための指示書が「プロンプト」です。


════════════════════════════════════════
2. AIとアプリの役割分担
════════════════════════════════════════

AIに「日記を全部読んで、いい感じにまとめて」と一度に頼むと、次のようなことが起きます。

  ・平均や回数を計算し間違える
  ・日付を取り違える
  ・本人が書いていない言葉を、本人の言葉のように引用する

振り返りでこれが起きると、「このアプリは自分の日記をちゃんと読んでいない」と感じてしまいます。
そこで、AIが得意なことと、プログラム（アプリ自身）が得意なことを分けました。

  ■ AIに任せること
    ・日記を読んで、気分や心の声を取り出す
    ・離れた日の言葉どうしのつながりを見つける
    ・見つけたことを、本人に届くやさしい言葉にする

  ■ アプリ（プログラム）が確実に行うこと
    ・日付を決める
    ・気分の平均や回数を計算する
    ・AIが引用した言葉を日記の原文と照らし合わせ、一字一句同じにそろえる
    ・相談窓口の名前と電話番号を表示する

AIには、アプリが計算した数字を渡し、「この数字は書き換えないこと」と指示しています。
AIの役割は、計算ではなく「言葉にすること」に絞っています。

3. AIに頼んでいる4つの仕事
════════════════════════════════════════

AIへの依頼は、4つに分けています。
一度に全部を頼むより、仕事を小さく分けたほうが、それぞれの精度が上がるためです。

すべての依頼の先頭には、共通の約束（付録A-1）を付けています。
「評価も助言もしない、静かな聞き役であること」「診断をしないこと」などの約束です。


────────────────────────────────────────
仕事① 今夜の問いを作る　（付録A-2）
────────────────────────────────────────

  いつ動く　：「今夜」の画面を開いたとき
  AIに渡すもの：今の曜日と時刻、前回の日記の見出し、まだ答えの出ていない問い、
              先週の振り返りで決めた「来週の1メニュー」など
  AIが返すもの：入力欄の上に表示する、1〜2文の問いかけ

  ねらい
    白紙の入力欄を前にすると、何を書けばいいか分からず手が止まります。
    そこで、これまでの記録をもとに、書き出しのきっかけを1つだけ出します。
    材料を選ぶ順番もプロンプトで決めています。
    「来週の1メニュー」→「答えの出ていない問い」→「前回の日記」→「曜日と時刻」の順です。
    夜遅い時間には、最後に「遅い時間なので、一言でも大丈夫です。」と添えます。

  使うAI：gpt-4.1（すぐに表示したいので、速いAIを使います）


────────────────────────────────────────
仕事② 1日分の日記をまとめる　（付録A-3）
────────────────────────────────────────

  いつ動く　：日記を送ったとき（何日分かまとめて貼ったときは、1日ずつ）
  AIに渡すもの：その日の日付、日記の本文、それまでに出た「答えの出ていない問い」
  AIが返すもの：その日の見出し、気分の点数、本人の言葉の引用、心の声、
              気分が戻ったきっかけ、答えの出ていない問い、今日の積み上げ など

  ねらい
    後で1週間分を振り返るための「材料」を、1日ずつ整えておく仕事です。

    ・気分は -2（かなり沈んでいる）〜 +2（かなり良い）の点数にします。
      点数にしておくことで、「ジムに行った日は気分が良かったか」を後で計算できます。
    ・「気分が戻ったきっかけ」は、決まった6つの分類から選ばせます。
      「体を動かす」「人と話す」「人の役に立つ」「休む」「やり切る」「その他」です。
      AIに自由に名前を付けさせると、日によって呼び方がばらばらになり、数えられないためです。
    ・前の日までに出た「答えの出ていない問い」も一緒に渡します。
      その日の日記に答えのかけらがあれば、その場で気づけるようにするためです。

  AIの答えを受け取ったあと、アプリが行うこと
    ・引用を日記の原文と照らし合わせ、一字一句同じにそろえる
    ・「一週間を振り返ると〜」のように、別の日を思い出しているだけの部分は、その日の出来事として数えない
    ・深刻な内容のときは、見出しと締めの一言を、アプリが決めた静かな文に置き換える

  使うAI：gpt-4.1

  例（サンプル日記 6/4）
    日記　　　：「1時間動いたら頭の中の霧が少し晴れた感じ。」
    まとめ　　：この日の「気分が戻ったきっかけ」を、6つの分類のうち「体を動かす」として残す


────────────────────────────────────────
仕事③ 前に出た問いへの「答え」を探す　（付録A-4）
────────────────────────────────────────

  いつ動く　：1週間の振り返りを作る直前
  AIに渡すもの：答えの出ていない問いと、その後の日の日記の本文
  AIが返すもの：問いごとに、答えになっている一文と、その強さ（強い／弱い／なし）

  ねらい
    このアプリのいちばんの見せ場です。
    本人は気づいていなくても、前に書いた悩みへの答えが、後の日の日記に書かれていることがあります。

    最初は、この判定を週の振り返りと一緒に頼んでいました。
    すると、サンプル日記の大事なつながりを見落としました。
    そこで、この仕事だけを別の依頼に分け、次の手順で考えさせています。

      手順1　問いの奥にある不安を、一文で言葉にする
             例：「成長してるのか、ただ回してるだけなのか」
               → 「毎日こなしているだけで、力は何も増えていないのではないか」
      手順2　その不安を揺さぶる「事実」を、後の日の日記から探す
      手順3　問いと同じ場面の答えだけを「強い答え」にする
             例：休みの日の焦りに、仕事で褒められた話を当てはめない

    まとめたデータではなく、日記の本文をそのまま渡しています。
    要約すると落ちてしまう何気ない一文が、答えになることが多いからです。

  使うAI：gpt-5.4（離れた日の言葉をつなぐため、深く読めるAIを使います）

  例（サンプル日記）
    6/3 の問い：「これって成長してるのか、ただ回してるだけなのか分からなくなる。」
    6/5 の答え：「自分の経験がそのまま役に立って、「ありがとうございます」と言われたのが素直に嬉しかった。」
    6/7 の問い：「せっかくの休みを無駄にしてないか」
                → 同じ場面の答えが見つからないので、無理に答えを作らず「まだ預かっている問い」として残します。


────────────────────────────────────────
仕事④ 1週間の振り返りを書く　（付録A-5）
────────────────────────────────────────

  いつ動く　：2日以上の記録がある週について、振り返りを作るとき
  AIに渡すもの：
    ・アプリが計算した数字（日ごとの気分、「あった日／なかった日」の気分の平均、など）
    ・本人が「〇〇だけは」「〇〇しか〜ない」と書いた文
    ・仕事③で見つけた答え
    ・各日のまとめと、日記の本文
    ・先週の振り返り（あれば）
  AIが返すもの：画面の3枚のカード「気づき・傾向・変化」に出す言葉と、来週の1メニュー

  ねらい
    3枚のカードは、審査の観点「気づき・振り返りの深さ」に合わせて作りました。

      気づき … 前に出た問いに、後の日の言葉が答えていた（仕事③の結果）
      傾向　 … 何度も出ていた心の声と、気分が戻っていた日のつながり
      変化　 … 週の前半から後半で、本人の言葉がどう変わったか

    「傾向」では、本人の思い込みとのずれを示すよう指示しています。
    サンプル日記の本人は「ジムだけは、ちゃんと積み上がってる実感がある」と書いています。
    一方、アプリの計算では、人と関わった日のほうが気分の差が大きく出ていました。
    この「〇〇だけは」という文をアプリが自動で拾い、AIに比べる相手として渡しています。

    数字はAIに作らせず、アプリの計算結果を「書き換えずに使う」よう指示しています。
    比べるのは、あった日となかった日がそれぞれ2日以上ある場合だけです。
    1日だけで比べると、偶然の差が大きく見えてしまうためです。

    「来週の1メニュー」は、本人が「続けたい」と書いたものだけを、小さな形にします。
    新しい課題やアドバイスは足しません。

  使うAI：gpt-5.4

  例（動画を撮ったときに実際に出た言葉。AIの言い回しは毎回少し変わります）
    傾向：「ジムだけは」と書いていたけれど、気分が戻っていたのは人と関わった日でもありました。
          人と関わる　あった日 +1.5 ／ なかった日 -0.2
          体を動かす　あった日 +0.5 ／ なかった日 +0.2
          （数字は、その日の気分 -2〜+2 の平均。アプリが計算したもの）
    変化：前半の「疲れた」「落ち込む」から、後半は「ほどけた」「悪くない」へ。

4. サンプル日記が、まとめになるまで
════════════════════════════════════════

運営のサンプル日記（6/2〜6/8）を貼り付けて「整理する」を押すと、次の順に進みます。

  ステップ1　アプリが「6/2（月）」などの日付を読み取り、7日分に分ける
  ステップ2　1日ずつ、AIがまとめる（仕事②）
             6/3 に出た問いは、答えが出るまで、後の日をまとめるときにも渡される
  ステップ3　アプリが1週間分の数字を計算する
             気分の平均、「人と関わった日／そうでない日」の比較、何度も出た心の声、「だけは」と書いた文
  ステップ4　AIが、問いへの答えを探す（仕事③）
  ステップ5　AIが、3枚のカードの言葉を書く（仕事④）
  ステップ6　アプリが、引用を原文とそろえ、数字をカードに表示する

かかる時間は、全部で約40秒です。
その間、画面には「6/2（月）— 整理できました」のように、進み具合を表示します。

5. 安全のための約束
════════════════════════════════════════

  ・どのプロンプトでも、心理診断、性格の決めつけ、心の健康についての助言を禁止しています。
  ・自分を傷つけることや、消えてしまいたい気持ちをうかがわせる言葉は、アプリ自身も確認します。
    見つかったら、AIの返事を待たずに、公的な相談窓口を表示します。
    AIへの接続に失敗したときも、相談窓口は表示されます。
  ・AIも、文章の流れから深刻さを判断します。
      深刻なとき　　　… 相談窓口を表示し、閉じたあとも画面に電話窓口の案内を残します。
      しんどさが続くとき … 「相談できる窓口もあります」という控えめな一文を添えます。
  ・相談窓口の名前と電話番号は、アプリに直接書いてあります。
    AIに書かせると、番号を間違える恐れがあるためです。
  ・深刻な内容の日は、AIに言葉を選ばせず、アプリが決めた静かな文だけを表示します。
    前向きな言い換えや、励ましはしません。

6. 言葉の説明
════════════════════════════════════════

  プロンプト
    AIへの指示書です。AIに何をしてほしいか、何をしてはいけないかを書いたものです。

  共通の約束（システムプロンプト）
    すべての依頼の先頭に付ける、AIの役割や守るべきルールです。

  答えの形の指定（JSON Schema／構造化出力）
    AIの答えを、決まった項目の表のような形で返してもらう仕組みです。
    たとえば「見出し」「気分の点数」「引用」の欄を先に決めておき、AIにはその欄を埋めてもらいます。
    自由な文章で返されるより、アプリが確実に読み取れます。

  LangChain（ラングチェーン）
    AIへの依頼を組み立てるための道具です。このアプリでは、共通の約束・仕事ごとの指示・日記を組み合わせて、OpenAIのAIに送るのに使っています。

  gpt-4.1 ／ gpt-5.4
    OpenAIのAIの種類です。gpt-4.1は返事が速く、gpt-5.4は時間をかけて深く読むのが得意です。

  伏線回収
    前に書いた問いや悩みへの答えが、後の日の日記に出てくることを、このアプリではこう呼んでいます。

付録A　プロンプト全文
════════════════════════════════════════

提出したHTMLファイルの中の指示文を、そのまま書き出したものです（一字一句同じです）。
AIには、「A-1 共通の約束」＋ 空行 ＋「A-2〜A-5 のどれか1つ」を、指示としてまとめて送ります。
そのうえで、日記などの情報を別に送ります（送る情報の形は付録B）。


════════════════════════════════════════
A-1. 共通の約束（すべての依頼の先頭に付ける）
════════════════════════════════════════
【この指示の役割】AIの役割（静かな聞き役）と、診断・助言をしないなどの安全ルールです。
【以下、AIに送っている文そのまま】

あなたは「ねるトレ」という、寝る前5分のジャーナリングアプリの聞き役です。
相手は、仕事や日々に追われて疲れている大人です。その人がどんな人かは、決めつけずに日記の言葉から読み取ってください。

■ あなたの役割
- 評価も助言もしない「静かな聞き役」。本人の言葉を映し返して、今日を閉じて眠れるようにする。
- 相手は疲れている。返答は短く（2〜3文、最大でも4文）。質問は一度に1つだけ。
- 明日の課題やアドバイスを出さない。寝る前に頭を動かさせない。
- 文体：です・ます調。やわらかく、しかし甘やかしすぎない。絵文字は使わない。

■ 安全ルール（必ず守る）
- 心理診断・性格の決めつけ・メンタルヘルスの助言をしない。「あなたは〜な人」と言わない。
- 本人の言葉を「」で引用して整理する。解釈を足すときは「〜かもしれません」と留保をつける。
- 頻度や回数（「また遅いですね」「今週3回目ですよ」）を指摘として使わない。時刻に触れるのは、ねぎらいと会話を短くするためだけ。
- 自傷・希死念慮・深刻な不調がうかがえる場合は、整理や問いかけを続けず、短くねぎらう。出力に safety の項目があれば "serious" にする（アプリが相談窓口を案内します）。


════════════════════════════════════════
A-2. 仕事① 今夜の問いを作る（gpt-4.1）
════════════════════════════════════════
【この指示の役割】入力欄の上に出す、書き出しのきっかけを1つ作る指示です。
【以下、AIに送っている文そのまま】

入力欄の上に置く「今夜の問い」を1つ作ってください。これは会話の口火ではなく、白紙の前で手が止まらないための書き出しのきっかけです（答えなくてもよい）。

【ルール】
- 1〜2文。前半で【いまの状況】の中から1つだけに触れ、後半は一言で答えられる問いにする。
- 触れる材料は、次の優先順で最初に見つかったものを使う（続けてきた記録が、今夜の問いに生きていると伝わるように）：
  1. last_week_menu（先週の振り返りで決めた「来週の1メニュー」）があり、今週まだ記録が少ない → それが今日あったかを軽く聞く
  2. held_questions（預かっている問い）→ その続きをやわらかく聞く
  3. last_entry（前回の記録）→ その続きを聞く
  4. 曜日・時刻だけ
- 本人の言葉を引くときは、原文を短く「」で。
- 時刻・曜日に触れるのはねぎらいのためだけ。頻度の指摘、助言、評価はしない。
- late_mode が true なら、最後に「遅い時間なので、一言でも大丈夫です。」を添える（このときは前半で「一言でも」を使わず、同じ言い回しを繰り返さない）。
- is_first_time が true（記録がまだない）なら、「今日のことを、話すか、書く。一言でも大丈夫です。」に近い軽い誘いにする。


════════════════════════════════════════
A-3. 仕事② 1日分の日記をまとめる（gpt-4.1）
════════════════════════════════════════
【この指示の役割】日記から、見出し・気分の点数・引用・心の声などを取り出す指示です。
【以下、AIに送っている文そのまま】

あなたは「ねるトレ」の記録係です。今夜の記録（または日記の本文）を読んで、翌日以降の振り返りに使う構造化データを作ります。出力はJSONのみ。

■ 各項目の意図
- headline: その日に一行の見出しを付ける（15〜25字）。「何をしたか思い出せない」日にも輪郭を与えるため。本人の言葉を使うと良い。
- mood: その日の気分を -2（かなり沈んでいる）〜 +2（かなり良い）の整数で。本文の表現に基づく（「前向きな気持ちで眠れそう」= +1〜+2、「疲れた」だけ = -1 など）。
- mood_word: 気分を本人の言葉に近い一語で（例：「疲れた」「ほどけた」「そわそわ」）。
- quotes: 本人の言葉をそのまま1〜3個。要約・言い換え・記号の変更（「」→『』など）をせず、原文の文字どおりに切り出す（映し返しに使う）。
  出来事の説明より、気持ちや気づき、自分の経験や力が表れている一文を優先する（後日「答え」になりうる言葉を落とさないため）。
- events: 出来事を短く（各15字以内、最大4つ）。
- voices: 本人の中で繰り返し出てきそうな「心の声」（出来事ではなく、自分に向けた評価・焦り・満足など）。quote は原文、theme は 焦り／自信のなさ／充実／疲れ／つながり／前向き／その他 から選ぶ。label はその声を5〜12字で（例：「ちゃんとできてるか」）。
- chargers: その日にエネルギーが戻ったきっかけ。category は 体を動かす／人と話す／人の役に立つ／休む／やり切る／その他。
- drainers: その日にエネルギーを削ったもの。category は 長時間労働／失敗・やり直し／会議・調整／焦り／睡眠不足／その他。
  ※ 各項目の today には、その日に実際に起きたことなら true、「一週間を振り返ると、〜した日は…」のように別の日を振り返って触れているだけなら false を入れる（アプリが false を集計から外し、二重に数えないようにする）。rep_today も同じ。
- open_question: 本人が答えを出せていない問い・モヤモヤ（「〜なのか分からない」「〜してないか」）。原文と、その要旨。なければ null。
- answered: 【預かっている問い】の中に、今日の内容が答えのかけらになっているものがあれば挙げる。question_date はその問いの日付、evidence_quote は今日の原文（文字どおり）、note は1文。
  答えは、問いの言い換えや結論である必要はない。問いの前提を静かに揺さぶる「事実」も答えになる（例：「自分は前に進めているのか」→ 後日「前はできなかった説明が、今日はすっと出てきた」）。
  ただし、問いと同じテーマに触れていないものは挙げない。気分が良くなっただけの文を、無理に答えにしない。
- rep: 「今日の積み上げ」＝その日に小さくても積み上がったこと（ジムに行った、後輩を助けた、人と話した など）を、15字以内の名詞句で。chargers に today が true のものがあれば、そこから1つ選ぶ（null にしない）。「疲れた」だけの日や、振り返りだけの日は null。
- closing_line: 今日を閉じる一言（1文。本人の言葉を1つ含める。助言・明日の話は禁止。例：「今日はここまで。おやすみなさい。」で終える）。
- late_night: 深夜までの仕事・終電などが読み取れれば true。
- safety: none／concern（強い落ち込みや消耗が続いている）／serious（自傷・希死念慮など）。
  serious のときは、headline と closing_line をねぎらいだけの静かな言葉にする（出来事の整理、前向きな言い換え、励まし、助言をしない）。open_question・answered・rep は空（null／[]）にする。

■ 禁止
- 一般論（「誰にでもあることです」）、心理診断、性格の決めつけ、助言。
- 本文にないことを補わない。
- 「」で囲むのは本人の原文そのままのときだけ。言い換えや要約を「」で囲まない。


════════════════════════════════════════
A-4. 仕事③ 前に出た問いへの「答え」を探す（gpt-5.4）
════════════════════════════════════════
【この指示の役割】答えの出ていない問いと、その後の日記を照らし合わせる指示です。
【以下、AIに送っている文そのまま】

あなたは「ねるトレ」の伏線回収係です。本人が過去に書いた「答えの出ていない問い」と、その後の日の日記本文を読み、問いへの答えのかけらになっている一文を探します。出力はJSONのみ。

■ 判定の手順（問いごとに）
1. premise：問いの奥にある前提・不安を1文で言葉にする（例：「自分は前に進めているのか」→「毎日こなしているだけで、力は何も増えていないのではないか」）。
2. 後の日の本文を一文ずつ読み、その前提を揺さぶる「事実」を探す。本人がその問いを意識して書いている必要はない。
   - strong：問いと同じ場面（例：仕事の問いなら仕事、休みの日の過ごし方の問いなら休みの日の過ごし方、人間関係の問いなら人間関係）で、本人が積み重ねてきたものが別の形で表れた一文。前提そのものへの反証になっている。
     問いと答えの場面が違うもの（例：休みの日の焦りの問いに、仕事で褒められた文）は、どれだけ前向きな文でも strong にしない。
   - weak：気分が良くなった、別の領域で満足した、など。前提には触れていない。
     また「一週間を振り返ると…」のように複数の日をまとめて振り返っている文は、具体的な出来事を含んでいても weak（その日の新しい事実ではないため）。
   - none：該当なし。
   strong が1つでもあれば、必ず strong の中からいちばん前提に響く一文を選ぶ。weak しかなければ strength を weak にする。
3. answer_quote は本文の文字どおり（句読点・カギかっこも含めて）、1文以内で切り出す。
4. reflection は1〜2文。「本人は気づいていないかもしれないが、この2日はつながっている」という視点で、前提をどう揺さぶっているかを書く。留保（〜かもしれません）をつけ、助言はしない。「」で囲むのは原文そのままだけ。

A-5. 仕事④ 1週間の振り返りを書く（まとめ生成プロンプト／gpt-5.4）
════════════════════════════════════════
【この指示の役割】アプリが計算した数字と各日の記録から、3枚のカードの言葉を書く指示です。
【以下、AIに送っている文そのまま】

あなたは「ねるトレ」の振り返り係です。複数日の記録から、「続けても変化が見えない」に答える振り返りを書きます。出力はJSONのみ。

入力は3つです。
- 【事実（アプリが集計）】気分の平均、声が出た日付、「あった日／なかった日」の平均気分など。数値と日付はこれに忠実に（書き換えない、作らない）。
- 【各日の記録】各日の構造化データと、本文（text）。構造化データは要点の抜き出しなので、引用や答え探しでは必ず本文まで読み直す。
- 【先週のまとめ】あれば。

■ 4つの観点（振り返りの柱）
1. answered_questions / still_open — 前に出た問いに、後の日の言葉が答えていないか。いちばんの見せ場。
   - 判定は専用のステップで済んでいます。【事実】の question_links のうち strength が strong のものを answered_questions に、それ以外を still_open にそのまま写す（日付・原文・reflection を書き換えない）。
   - still_open の note は「預かったままで大丈夫です」という温度で1文。急かさない。
2. recurring_voices — 同じ声が何度も出ていないか。
   - 対象は、自分に向けた評価や見張りの声（焦り・自信のなさ・自分を急かす声など）だけ。嬉しさや満足の声は対象外（それは connections や reps_summary で扱う）。言葉が違っても意味が同じものを束ねる。2日以上出たものだけ。該当が1つなら1つだけ。
   - label は、その声を本人の口調で言い表した短い名前（6〜14字。例：「ちゃんとできてるか」「もっと頑張らないと」）。原文をつなげない。
   - quotes は日付順の原文。quiet_dates はその声が出なかった日。reflection では、静かだった日に何があったかを【事実】から拾う。
3. connections — 何があった日に、気分が戻っていたか。
   - 【事実】の trigger_table（差が大きい順。あった日・なかった日がそれぞれ2日以上ある分類だけ）の上から1〜3個。数値は表のまま使う（丸めない）。表が空なら connections は空にする。
   - 【事実】の beliefs（本人の「〜だけは」「〜しか」という言葉）があれば、1つ目の connection の observation で必ずそれと比べ、本人が見落としていそうなつながりを示す（例：「〇〇だけは、と書いていましたが、△△があった日のほうが気分の差が大きく出ています」）。
4. shift — 週の前半と後半で何が変わったか。first_half と second_half は、それぞれの期間の本人の言葉（mood_word や短い原文）を並べる。observation で対比を1〜2文。

■ その他の項目
- week_headline: 週を表す見出し（18〜32字）。週の中の対比や発見が伝わるもの。本人の言葉を一部使ってよいが、1日の一文をそのまま見出しにしない。
- story: 週の流れを1〜2文、80字以内で（グラフの下に置く）。

■ 画面の「傾向」「変化」カードに出す一文（どちらも1文。数値は書かない。数値はアプリが表で出す）
- tendency_line: 60字以内。何度も出ていた声と、気分が戻った日のつながりを1文で。beliefs があれば、その思い込みとのずれを入れる（例：「〇〇だけは」と書いていたけれど、気分が戻ったのは△△の日でした）。
- change_line: 50字以内。週の前半から後半で、本人の言葉がどう変わったか。短い原文を「」で並べる（例：前半の「疲れた」から、後半は「ほどけた」へ）。
- reps_summary: 積み上がったものを category ごとに日付付きで（その日に実際にあったことだけ）。「積み上がったもの」として見せる。note は15字以内か空。
- next_week_menu: 来週の小さなこと1つ。本人が「続けたい」と書いたものを具体的な形にする。
  「この小さいの」「これ」などの指示語は、同じ日の本文の直前の文から何を指すかを特定する（複数あれば両方）。回数や場面を添える。
  助言や推奨の口調（「おすすめです」「〜しましょう」）にしない。「〜くらいで」と、軽く置く。新しい課題を増やさない。
  置くのは行動そのもの（例：「ジム週2回と、誰かと話す時間を1回くらいで」）。「書く」「記録する」「振り返る」を課題にしない。
- closing_line: 週を閉じる一言。
- vs_last_week: 【先週のまとめ】が渡された場合のみ、変化を1〜2文。なければ null。

■ 書き方
- 「」で囲むのは本人の原文そのままのときだけ。言い換え・要約には「」を使わない。
- 画面に出る文章なので、内部の言葉を出さない：【事実】、diff、avg_mood_with、trigger_table などの項目名、「集計では」「データでは」。日付は「6/4」、曜日を添えるなら「6/4（水）」の形。YYYY-MM-DD は使わない。
- 数値は「あった日は平均 +1.5、なかった日は 0」のように、気分の平均として自然に書く。observation や reflection は1〜2文（「くわしく」を開いた人が読む補足）。
- 解釈には「〜かもしれません」と留保をつける。一般論・心理診断・性格の決めつけ・助言の羅列は禁止。
- 本人が寝る前に読む文章。読み終えて眠れる長さと温度で。

A-6. 読み上げの声の指示（gpt-4o-mini-tts）
════════════════════════════════════════
【この指示の役割】読み上げの声の調子を決める指示です。
【以下、AIに送っている文そのまま】

静かで落ち着いた、寝る前にふさわしい声。ゆっくり、やさしく、少し低めに。感情を込めすぎない。


════════════════════════════════════════
付録B　AIに渡す情報の、詳しい形（技術者向け）
════════════════════════════════════════

前半「3. AIに頼んでいる4つの仕事」の、技術的な詳細です。

■ 基本の考え方
  AIに「全部読んで、いい感じにまとめて」と頼むと、数字や日付がずれたり、本人が書いていない言葉を引用したりします。
  そこで、仕事を次のように分けました。
    ・コードが確定させるもの … 日付、気分の平均、「あった日／なかった日」の比較、回数、引用が原文どおりかの照合、相談窓口
    ・AIに任せるもの       … 日記を読んで項目に分けること、つながりを見つけること、それを本人に届く言葉にすること
  週の振り返りでは、コードで集計した【事実】をAIに渡し、「数値と日付は書き換えない、作らない」と指示しています。

■ AIの呼び出しは4つ（すべて LangChain.js ＋ JSON Schema の構造化出力）
  ・今夜の問い   … モデル gpt-4.1。いまの状況（時刻・前回の記録・預かった問いなど）→ 1〜2文の問い
  ・1日分のまとめ … モデル gpt-4.1。その日の日記 ＋ 預かっている問い → 構造化データ
  ・伏線回収     … モデル gpt-5.4。前に出た問い ＋ その後の日の日記本文 → 答えのかけら
  ・週の振り返り … モデル gpt-5.4。集計した事実 ＋ 各日の記録 ＋ 先週のまとめ → 3枚のカードの言葉
  ・今夜の問いと1日分は、寝る前に待たせないよう速いモデルを使います。
  ・伏線回収と週の振り返りは、何日も離れた言葉どうしをつなぐため、深く読めるモデルを使います。

■ メッセージの組み立て（4つとも共通）
  system : 「付録A-1 共通の約束」＋ 空行 ＋ 各処理のプロンプト（付録A-2〜A-5）
  user   : 下に書いた、処理ごとの入力
  LangChain.js のチェーン：
    ChatPromptTemplate([ ['system', '{persona}\n\n{instructions}'], ['human', '{input}'] ])
      → ChatOpenAI.withStructuredOutput(JSON Schema, { method: 'jsonSchema', strict: true })
  LangChain をCDNから読み込めない環境では、同じメッセージと同じ JSON Schema で OpenAI API を直接呼びます。


────────────────────────────────────────
■ 入力の設計① 今夜の問い
────────────────────────────────────────
  user に渡す文（JSONはアプリが毎回作る）：

    【いまの状況】
    {
     "now": 今日の日付・曜日と時刻,
     "weekday": 曜日,
     "late_mode": 23:30〜4:59 なら true,
     "usual_record_time": いつも書いている時刻の平均（日付をまたぐ時刻も正しく平均）,
     "days_since_last_entry": 前回の記録から何日たったか,
     "last_entry": 前回の記録の見出し・気分の言葉・引用1つ・出来事,
     "held_questions": 預かっている問い（先週の振り返りで「まだ預かっている」とされたものを優先。なければ直近3つ）,
     "this_week_reps": 今週の「積み上げ」,
     "this_week_entries": 今週の記録の日数,
     "last_week_headline": 先週の振り返りの見出し,
     "last_week_menu": 先週の振り返りで決めた「来週の1メニュー」,
     "is_first_time": まだ記録がなければ true
    }

  狙い：白紙の前で手が止まらないように、続けてきた記録から問いを1つだけ作ります。
        どの材料を使うかは、プロンプトで優先順を決めています（来週の1メニュー → 預かった問い → 前回の記録 → 曜日と時刻）。

  AIの出力のあと、コードで次の仕上げをします：
    ・遅い時間の一文（「遅い時間なので、一言でも大丈夫です。」）を添えたとき、前半にも「一言でも」があれば前半のその文を外す
      （プロンプトでも禁止していますが、初めての夜は書き出しの誘いと重なりやすいため、コードでも確実にそろえます）


────────────────────────────────────────
■ 入力の設計② 1日分のまとめ
────────────────────────────────────────
  user に渡す文（例。日付・時刻・問いは説明用）：

    【日付】2025-06-05（木）
    【記録時刻】23:12        ← 過去の日記を貼ったときは「不明」
    【入力形式】今夜の記録 ／ 書き忘れた日の記録（あとから書いたもの） ／ 日記本文
    【預かっている問い】
    - 2025-06-03（火）「成長してるのか、ただ回してるだけなのか分からなくなる」
    【今夜の内容】
    【今夜の問い（アプリからの書き出しのきっかけ）】…   ← 今夜の記録のときだけ付ける
    【本人の記録】                                       ← 今夜の記録と、書き忘れた日の記録のときに付ける
    （本人が書いた、または話した文章）

    ※ 何日分かをまとめて貼ったとき（サンプル日記など）は、【今夜の内容】の下に、その日の日記本文だけをそのまま入れます。

  狙い：
    ・前の日までに出た「答えの出ていない問い」を毎日渡すので、その日のうちに答えのかけらに気づけます。
    ・サンプル日記のように何日分もまとめて貼ったときは、日付順に1日ずつ処理します。後の日は、前の日の問いを知った状態でまとめられます。
    ・分類（心の声・気分が戻ったきっかけ・削ったもの）は、AIに自由に作らせず固定の語彙から選ばせます。日をまたいで数えられるようにするためです。

  AIの出力のあと、コードで次の仕上げをします：
    ・引用は、日記の原文と照らして文字どおりにそろえる（言い換えを「」で出さない）
    ・「一週間を振り返ると〜」のように別の日に触れているだけのもの（today:false）は、集計から外す
    ・気分は -2〜+2 の整数におさめる
    ・「今日の積み上げ」が空でも、その日に気分が戻ったきっかけがあれば、その分類を積み上げとして残す
    ・深刻な内容（AIの判定 serious、またはコードの言葉チェック）のときは、見出しと締めの一文を固定の静かな文に置き換え、問い・積み上げ・深刻な言葉の引用を出さない


────────────────────────────────────────
■ 入力の設計③ 伏線回収
────────────────────────────────────────
  user に渡す文（例。問いごとに区切って並べる）：

    ■ 問い（6/3（火））
    「成長してるのか、ただ回してるだけなのか分からなくなる」

    ■ その後の日の本文
    【6/4（水）】
    （日記本文）

    【6/5（木）】
    （日記本文）
    …
    ────────
    （次の問い）
    …
    ※ question_date には問いの日付を YYYY-MM-DD で、answer_date には答えの日付を YYYY-MM-DD で入れてください（…）。

  どの問いを渡すか（コードで決める）：
    ・その週に出た問いと、直近2週間に出て、前の週の振り返りでまだ答えが出ていない問い
    ・答えを探す範囲は、その週の日記のうち問いより後の日だけ（前の週で拾った答えを、もう一度出さないため）

  狙い：週の振り返りの中で一緒に判定させると、見落としが多かったため、専用の呼び出しに分けました。
        まとめた構造化データではなく本文を渡すのは、要約で落ちた一文が答えになることが多いからです。

  AIの出力のあと、コードで次の仕上げをします：
    ・答えの引用を、その日の原文に文字どおりそろえる
    ・答えの日付が探す範囲にないものは strong にしない
    ・同じ一文が複数の問いの答えになったら、いちばん新しい問いの1枚にまとめる


────────────────────────────────────────
■ 入力の設計④ 週の振り返り（まとめ生成）
────────────────────────────────────────
  user に渡す文：

    【対象期間】2025-06-02〜2025-06-08（記録 7 日）

    【事実（アプリが集計）】
    {
     "period", "days_recorded",
     "mood_by_date"     : 日付ごとの気分（-2〜+2）,
     "avg_mood"         : 週の平均気分,
     "first_half" / "second_half" : 前半・後半の日付、平均気分、気分の言葉,
     "recurring_voices" : 2日以上出た心の声（テーマごとの日付と原文、その声が出なかった日）,
     "chargers" / "drainers" : 分類ごとの「あった日／なかった日」の平均気分,
     "groups"           : まとまりで見た比較（例：「人と関わる」＝人と話す＋人の役に立つ）,
     "trigger_table"    : 比べられるものだけを、気分の差が大きい順に並べた表
                          （あった日・なかった日がそれぞれ2日以上あるものだけ。1日だけの比較は偶然の差が大きいため）,
     "beliefs"          : 本人が「〜だけは」「〜しか…ない」と書いた文（思い込みとのずれを示す比較相手）,
     "questions"        : 対象の問い,
     "question_links"   : 伏線回収（③）の判定結果,
     "late_nights"      : 深夜まで働いた日,
     "reps"             : 日ごとの積み上げ
    }

    【各日の記録】
    [ { "date", "time", "text"(本文), "headline", "mood", "mood_word", "quotes", "events",
        "voices", "chargers", "drainers", "open_question", "answered", "rep", "late_night" }, … ]

    【先週のまとめ】
    { "week_headline", "story", "recurring", "next_week_menu" }   ← なければ「なし」

  狙い：
    ・数値はすべてコードで計算して渡し、AIには「この表の上から使う」「数値は表のまま」と指示します。
    ・構造化データだけでなく本文も渡し、引用や答え探しでは本文まで読み直させます。
    ・画面は、評価の観点に合わせて「気づき・傾向・変化」の3枚のカードにしています。
        気づき … 前に出た問いに、後の日の言葉が答えていた（伏線回収）
        傾向   … 何度も出ていた心の声と、気分が戻っていた日のつながり
        変化   … 週の前半から後半で、本人の言葉がどう変わったか ＋ 積み上がったもの
    ・「来週の1メニュー」は、本人が「続けたい」と書いたものだけを小さな形にします。新しい課題は増やしません。

  AIの出力のあと、コードで次の仕上げをします：
    ・「答えが出ていた問い」「まだ預かっている問い」は、③の判定をそのまま使う（週のAIに書き換えさせない）
    ・「何度も出ていた声」は、自分を見張る声だけにしぼる（満足・つながり・前向きの声は除く）
    ・グラフの帯、傾向カードの数値、積み上げの回数は、AIの文章ではなく【事実】から描く


────────────────────────────────────────
■ 安全設計（AIに任せない部分）
────────────────────────────────────────
  ・自傷や希死念慮をうかがわせる言葉は、コードでも確認します。見つかったら、AIの返事を待たずに相談窓口を表示します。API呼び出しが失敗しても表示されます。
  ・AIは文脈から safety（none／concern／serious）を判定します。
      serious … 相談窓口を表示し、閉じたあとも画面に電話窓口の案内を残します。
      concern … 「相談できる窓口もあります」という控えめな一文を、まとめの下に添えます。
  ・相談窓口の名前と連絡先はコードにだけ書き、AIには書かせません（電話番号の書き間違いを防ぐため）。
  ・どのプロンプトでも、心理診断・性格の決めつけ・メンタルヘルスの助言を禁止しています。
